# Profiles
A profile decides which parts of a description a build compiles. Marking a statement with `@profile` compiles it only when that profile is active, which keeps debug tooling out of the game you ship without keeping a second description file.

```blink copy
-- validate writes while developing, trust your own code in the shipped game
@profile("dev")
option WriteValidations = true

-- a debug remote that must never reach a live server
@profile("dev")
event GiveMoney {
    From: Client,
    Type: Reliable,
    Call: SingleSync,
    Data: u32
}

-- a whole debugging library, imported only into dev builds
@profile("dev")
import "./debugger"
```

There are four profiles: `dev`, `debug`, `test` and `release`. A statement without `@profile` is compiled under every one of them.

## Choosing a Profile
The command line takes the profile with `--profile` (or `-p`):
```sh copy
blinkblox file-name --profile dev
```
In the Studio plugin, set a string attribute named `Profile` on the description file in `ServerStorage.BLINK_CONFIGURATION_FILES`.

<Callout type="warning">
    A build without a profile is compiled as `release`. That is deliberate: a statement marked `dev` is one somebody meant to keep out of the shipped game, so a build that forgot the flag leaves it out rather than ships it.
</Callout>

## What Can Be Marked
`@profile` goes in front of a type (`type`, `struct`, `enum`, `map`, `set`), an `event`, a `function`, a `scope`, an `import` or an `option`. Everything inside a marked scope or import follows it.

## Rules
- **A compiled declaration cannot use an excluded one.** If `Ping` is compiled and uses a type marked `dev`, a `release` build is refused with `E3027` rather than quietly carrying the type into the build. Mark both, or neither.
- **Names stay unique across profiles.** Two declarations with the same name are a duplicate even under different profiles.
- **An option may be set once per profile**, and once without one. `@profile("dev")` and `@profile("release")` may each set `MaxPacketSize`. Setting it both with and without a profile is refused under every profile, so a description is valid in all builds or in none.
- **A misspelt profile is an error** (`E3026`), not a statement that silently never compiles.

<Callout type="info">
    The client and server must be built with the same profile. Their schema signatures differ otherwise, and they refuse each other when the game starts rather than decoding one event as another.
</Callout>
