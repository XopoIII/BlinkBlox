# Functions
Functions are Blink's version of Roblox's `RemoteFunction`.<br/>
They provide a way for one side to ask the other a question and wait for the answer.

## Usage in Blink

Functions can be defined using the `function` keyword.
```blink copy
function MyFunction {
    Yield: Coroutine,
    Data: f64,
    Return: f64
}
```

#### `From`
Default: `Client`

Determines which side **invokes**. The other side listens.

```blink copy
-- The client asks the server. The default, and what every function did before this existed.
function GetBalance {
    Yield: Coroutine,
    Data: u8,
    Return: u32
}

-- The server asks a client, and names which one.
function GetClientSetting {
    From: Server,
    Yield: Coroutine,
    Data: u8,
    Return: string
}
```

```lua filename="server.luau" copy
local Answer = Net.GetClientSetting.Invoke(Player, 1)
```
```lua filename="client.luau" copy
Net.GetClientSetting.On(function(Which)
    return Settings[Which]
end)
```

<Callout type="warning">
    Asking a client a question means trusting a client's answer, and waiting on one. A client may
    reply with anything its schema allows, may take as long as it likes, and may never reply at all --
    in which case the call fails after [`InvocationTimeout`](1-options#invocationtimeout).

    Treat the return value as you would any other data from a client, and do not hold anything
    important -- a lock, a queue slot, a request handler -- across the call.
</Callout>

`Rate` and `Burst` are ignored on a `From: Server` function, exactly as on a `From: Server` event:
rate limiting applies to inbound traffic, and the server is the party being protected.

#### `Yield`
Determines the library used to handle yielding to the requester.<br/>
* `Coroutine` - The builtin Luau coroutine library.
* `Future` - The user provided future library, use of redblox's future library is recommended.
* `Promise` - The user provided promise library, use of evaera's promise library (or forks of it) is recommended.

#### `Rate`, `Burst`
Limits how often one player may invoke this function, exactly as on
[events](5-events#rate-burst). Applies only to a `From: Client` function -- the default.

A refused invocation is answered with a failure rather than dropped, so the caller raises promptly
instead of waiting out the [timeout](1-options#invocationtimeout).

#### `Data`
The data sent to the server by the client.<br/>
For more information take a look at the [data field](./5-events.mdx#data) for events.

#### `Return`
The data returned by the server to the client.<br/>
For more information take a look at the [data field](./5-events.mdx#data) for events.

`Data` and `Return` may name their [type pack](./5-events.mdx#type-packs) elements the same way --
`Data: (id: u8, label: string)` alongside `Return: (id: u16, label: string)` is fine. The generated
code keeps the two sets apart, so there is no need to invent distinct names for the same thing going
each way.

## Usage in Luau

### Invoking a Function
```lua filename="client-coroutine.luau" copy
local Value = blink.MyFunction.Invoke(5)
```
```lua filename="client-future.luau" copy
local Future = blink.MyFunction.Invoke(5)
local Value = Future:Await()
```
```lua filename="client-promise.luau" copy
local Promise = blink.MyFunction.Invoke(5)
local Value = Promise:await()
```

### Listening to a Function
```lua filename="server.luau" copy
blink.MyFunction.On(function(Player, Value)
    return Value * 2
end)
```
